# SSI daily fallback duplicates: 2026-10-20

Scope: daily generate / publish-site / send-channel. Weekly quality hold and
the WhatsApp freeze are unchanged. No report resend is part of this repair.

## Confirmed cause

Four automatic index cron executions at 16:00, 16:05, 16:10 and 17:00 UTC each
processed the previous business date (19.10) and current date (20.10). The owner
observed four pairs, eight messages in total. Vercel request logs confirm two
JSON failures per execution; the last pair occurred at 17:02:16 / 17:02:53 UTC.

PostgreSQL logs for those requests show SQLSTATE 22P02, parameter $8 of the
MediaHubReport insert, detail `Unicode low surrogate must follow a high
surrogate.` The content ended an excerpt with an orphan `\ud83d` after the
yield phrase `5,88 т/га`. UTF-16 string truncation can split an emoji in half;
JavaScript JSON serialization accepts that escape, PostgreSQL jsonb does not.

The fallback sender called Telegram directly, bypassing the normal report
claim, sent timestamp and message-ID receipts. It neither checked previous
delivery nor persisted its successful sends. Retries therefore resent both
dates. The 19.10 report retained its earlier normal-send receipt; the 20.10
report had no receipt despite the fallback messages observed in the channel.

## Repair contract

- Evidence truncation preserves Unicode pairs. Report/source JSON serialization
  repairs orphan surrogates before hashing and database persistence.
- Automatic historical index repair does not generate/send historical reports.
  Explicit dated operator workflows remain separate.
- Fallback must be stored durably and sent through the same atomic sender as
  the normal report. Failed storage never permits a direct Telegram send.
- SSI daily and weekly sends checkpoint confirmed message IDs. A null element
  means an ambiguous in-flight attempt: automatic retries stop for operator
  reconciliation. Known rejection may retry; ambiguous timeout must not fall
  through to another sender. Do not erase receipts or force resend blindly.
- Already-sent reports are not regenerated by the automatic daily path.

Regression coverage: split-emoji JSON, fallback storage failure, concurrent
claims, already-sent/ambiguous deliveries, and the four-runs/two-dates incident.
Verification must not invoke a production send or fabricate historical message
IDs. Existing channel duplicates require a separate authorized cleanup.
